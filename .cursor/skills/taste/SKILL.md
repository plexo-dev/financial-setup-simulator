# Taste

Use this skill as a quality filter before proposing or shipping UI. The goal is not decoration; it is clarity, confidence, and a product that feels deliberate.

## Taste Principles

- Start with the user's intent: make the primary action and primary information impossible to miss.
- Prefer fewer, stronger choices: fewer colors, fewer type sizes, fewer effects, fewer competing focal points.
- Use contrast intentionally: scale, spacing, brightness, motion, and depth should all create hierarchy.
- Make the page feel composed: align edges, repeat spacing, keep rhythm consistent, and avoid orphaned elements.
- Use motion as feedback or storytelling, not ambient noise. Respect reduced motion.
- Treat charts as part of the interface. They should support comprehension, not fight the product.
- Remove anything that cannot explain why it exists.

## Review Checklist

- **Hierarchy**: Can the user tell what matters in the first 3 seconds?
- **Density**: Is information grouped into scannable chunks with enough breathing room?
- **Contrast**: Are primary/secondary states visually distinct without being loud?
- **Alignment**: Do layout edges and baselines line up across sections?
- **States**: Are loading, empty, error, hover, active, focused, and disabled states designed?
- **Copy**: Is text specific, short, and useful? Avoid vague headings and generic CTAs.
- **Motion**: Does animation clarify cause/effect? Is it interruptible and accessible?
- **Polish**: Are radii, shadows, borders, and spacing used consistently?

## Output Format

When reviewing UI, respond with:

1. What works.
2. What feels off, ordered by impact.
3. A concrete improvement plan with 3-7 changes.

When implementing UI, use this skill before code to define the visual intent.
